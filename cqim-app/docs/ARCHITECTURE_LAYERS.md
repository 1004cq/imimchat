# CQIM 分层架构说明（半页）

## 为何不采用 C++ / MTProto / TDLib

| 方案 | 不采用的原因 |
|------|----------------|
| **MTProto + TL schema** | 与现有 HTTP/JSON + WebSocket 客户端、Node 业务栈不兼容；引入全新序列化与握手，迁移成本高于收益。 |
| **TDLib（C++ 客户端库）** | TDLib 绑定的是 Telegram 协议与数据模型，不是「可插拔同步层」；我们只需其**职责划分**（seq、client_msg_id、重连补拉），不需其协议实现。 |
| **C++ 重写服务端** | 当前瓶颈在接入扩展与跨节点路由，Go Gateway + Redis 已覆盖；业务迭代在 Node/TS，重写服务端会拖慢交付且无协议收益。 |
| **Matrix 迁移** | 另一套联邦协议与房间模型，与现有私聊 Signal / 群 MLS 路径冲突，本轮禁止。 |

**结论**：学 Telegram **分层思想**，保留 CQIM 自有传输与加密栈，避免把协议栈换成 MTProto 生态。

## 当前分层对应关系

```
┌─────────────────────────────────────────────────────────────┐
│ Web 客户端（TypeScript + React）                             │
│  - UI / ChatDetail 稳定性、ErrorBoundary                     │
│  - privateSync：client_msg_id、seq 游标、重连 afterSeq 补洞   │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP JSON + WebSocket（文本帧）
┌───────────────────────────▼─────────────────────────────────┐
│ 接入层：Go Gateway                                           │
│  - GATEWAY_ID、user:online:{uid} TTL 90s 条件续期/删除        │
│  - SUBSCRIBE cqim:im:push 跨节点投递                         │
│  - Nginx：/api least_conn，/signal、/ws/group ip_hash       │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│ 业务层：Node（Express）                                       │
│  - 会话、用户、群、媒体 API                                   │
│  - private-message-core：发信唯一写库出口                       │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│ 同步层（学 TDLib 职责，非 TDLib 协议）                        │
│  - per-chat seq；client_msg_id 幂等                           │
│  - 先写库再推（WS / Redis Pub/Sub / Push）                    │
│  - 重连按 afterSeq 补洞，不假设 WS 必达                       │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│ 加密层                                                        │
│  - 私聊：强制 Signal 信封 msgType=encrypted，禁止明文旁路      │
│  - 群聊：现有 MLS/E2EE 路径                                  │
└─────────────────────────────────────────────────────────────┘
```

双节点部署与 EdgeOne 源站策略见 [TWO_NODES.md](./TWO_NODES.md)：**源站只回第一台**，不在 EdgeOne 源站组拆 WebSocket。
