# E2EE lifecycle repair — 2026-10-04

## Scope and cause

This branch fixes private-chat lifecycle/interop defects, not a new algorithm:

- Native emitted v2 `recipient*PreKeyId` fields; older Web emitted `used*PreKeyId` and no version. Both names are now supported; conflicting IDs fail closed.
- Native legacy signed-prekey signatures were public-key strings. Upgrade generates an ECDSA signing pair and re-signs the **same** prekey, preserving its private half. Web migration also re-signs in place rather than replacing an issued ID.
- Failed history, missing OPKs and invalid ciphertext used to replace/erase live sessions or consume a private OPK before authentication. Decrypt now operates on a candidate and commits only after AES-GCM succeeds. Native history/realtime failures no longer automatically reset the peer.
- Whole native read/derive/save operations now run through an async task gate. Web uses per-peer queues plus origin-wide Web Locks when available, including between Worker/main thread/tabs. Native reset also uses the same gate.
- Bounded skipped-message keys support out-of-order delivery; replayed counters and retired ratchets cannot rewind the active session.
- Existing native local history no longer requires a key-directory request. A failed count request is not treated as an empty pool.
- Repository Node crypto routes now require login and reject writes to another user's key directory. Web and its Worker provide the bearer token.
- Signal upgrades also require a valid, non-banned session, bind socket identity to that session and fail closed on lookup errors. All four browser signal callers attach the login token; URLs are not logged. Explicit native peer-reset requests are forwarded only to existing private-chat peers and handled on Web's serialized Worker queue. React edits preserve effect cleanup and existing handler refs. The existing Zustand store annotation is corrected to `StoreApi`, not its curried factory type.
- The Node directory issues OPKs within a PostgreSQL transaction/advisory lock and retains consumed-ID tombstones on re-upload. Full registration prunes stale available public keys; changing identity starts a new pool. Web reserves monotonic safe-integer OPK IDs and refuses local private-key overwrites.

The transaction lock is released by PostgreSQL at transaction end; see the [PostgreSQL advisory-lock reference](https://www.postgresql.org/docs/current/functions-admin.html). It uses Prisma's tagged `$executeRaw` to avoid deserializing a `void` result; see [Prisma v6 raw-query documentation](https://www.prisma.io/docs/orm/v6/prisma-client/using-raw-sql/raw-queries).

## Reproduce verification

Use the `packageManager` pinned in package.json (pnpm 10.4.1), not a global pnpm 11 that ignores the repository's existing patch/override settings.

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm exec prisma generate
pnpm test
IMIM_NATIVE_E2EE_SOURCE=/absolute/native/checkout/ios/App/App/E2EEEnvelope.swift pnpm test
pnpm build
```

Without the native source environment variable, native interop tests are explicitly skipped. With it, the harness compiles the **production Swift source** using `E2EE_REGRESSION_TESTS`, a memory-only store and network stub. It never accesses application Keychain data or real chat credentials. Synthetic private keys are generated in memory, not checked into Git or printed.

Verified locally: **44 tests passed / 12 files**, including 4 Web Crypto ↔ CryptoKit interop cases (both first-message directions, replies/new ratchet, concurrent native sends, tampered/replayed/missing-OPK/late messages). Web Vite + Node esbuild production build passed. Unsigned generic iOS Debug build using the full Xcode workspace passed.

Server-route tests use a transactional **database mock**, not a live PostgreSQL instance. The full repository `pnpm check` still has pre-existing unrelated type errors (legacy sticker/channel modules, call UI dependency, message/profile fields and Prisma model drift); it is **not** claimed green. Dependency manifests/lockfiles, Nginx and Compose are unchanged.

## Release and remaining work

Nothing was deployed, no server container was restarted, and no new TestFlight build was uploaded by this task. This repository's current main contains the Node server; the earlier production Go deployment is a separate implementation. These Node route fixes must not be represented as production Go fixes.

Release requires a coordinated backend/Web/native rollout, followed by two-account device tests: Web→iPhone, iPhone→Web, refresh history while sending, duplicate/late messages, network interruption and account switching. Confirm the deployed directory stores/returns `signingPublicKey` and uses the authenticated token from each client. Do not use a public production `get-bundle` request as a harmless probe: it consumes an OPK.

Still outstanding:

- Account-scoped directory storage is **not** real per-device support. Separate device registrations, recipient-device routing, per-device sessions, revocation and encrypted history transfer remain a coordinated protocol project. Browser account switching also needs isolated stores. Do not overwrite existing account identity keys as a workaround.
- Lost private keys cannot recover old ciphertext. This patch prevents future failures from damaging healthy sessions; it does not restore already lost message keys.
- The legacy repository `verify-message` HMAC derived from a public key is not sender authentication; this patch does not rely on it and does not certify the overall protocol as independently audited Signal.
- MLS group state/joining and media envelope interoperability are separate from these private-text lifecycle tests.
- Persisted older OPK pools do not contain historic tombstones. New issuance is protected going forward; past duplicate issuance cannot be retroactively identified from an empty available pool.

Never log message plaintext, private key material or bearer tokens. Keep unrelated dirty checkout changes separate from these commits. Do not run deploy.sh or broad Docker rebuild/restart commands for this repair.
